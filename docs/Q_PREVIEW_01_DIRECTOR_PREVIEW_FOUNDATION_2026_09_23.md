It refuses a running Preview, takes maintenance locks, snapshots/verifies every profile, records the selected profile and previous build, and writes an interrupted-transaction marker before registration. It uses same-identity `Add-AppxPackage -Register`, never uninstall/reinstall. Success appends a new receipt; previous stages, snapshots and transaction records remain available.

Refresh ends closed after its smoke. Start-menu activation or the external Launch command resumes ordinary use. There is no updater/service, automatic refresh, binary rollback or persisted-data rollback. An interrupted refresh blocks other tooling; explicit `-Resume` permits only the exact retained stage/receipt with unchanged data. A discrepancy remains a preservation boundary requiring diagnosis. Fault injection is restricted to the external tooling's named before/after-registration checkpoints, not Product behavior.

Compatible refresh preserves data. An incompatible source must be refused or use a new profile after explicit disposition; snapshots are not silently restored.
