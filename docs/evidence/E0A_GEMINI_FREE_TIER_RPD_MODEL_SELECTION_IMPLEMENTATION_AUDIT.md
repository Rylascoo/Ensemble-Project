## RPD admission

The current run path performs, for each accepted turn, three sequential role invocations. Each role performs one exact `countTokens` request and at most one generation request. The local conservative upper bound is therefore six Gemini API-bound operations per accepted turn.

```text
3.5 Flash-Lite: 12 turns × 6 = 72 <= 500 RPD
3.1 Flash-Lite: 12 turns × 6 = 72 <= 500 RPD
2.5 Flash-Lite:  3 turns × 6 = 18 <=  20 RPD
```

The code carries `RequestsPerDay`, `AcceptedTurnCap`, and the six-request bound in each profile and fails profile validation if a live-selectable route cannot cover its complete local worst-case run. It does not pretend to know traffic generated by other processes or users; remaining daily account capacity remains an external pre-live verification item.
