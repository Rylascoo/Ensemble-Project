# Claude Project Chat Independent Review — Director Amendment

Status: DIRECTOR-APPROVED OPERATING-LAW AMENDMENT / READ-ONLY CHAT ADVISORY LANE / CLAUDE CODE UNCHANGED
Date: 2026-09-19
Parent authority: `docs/PROJECT_AUTHORITY.md`

## Director decision

The Director approves Claude **Project Chat** as a concurrent independent review, falsification, and strategic-advisory lane for Ensemble / Kymaean.

This is a narrow operating-law amendment. It does not create another project manager, Engineering authority, Design authority, Administrator, merge authority, execution queue, provider authority, or product/ODR authority.

Claude Project Chat may run concurrently with other project work because this admitted form holds **no repository write lease and no worktree writer ownership**.

## Read-only boundary

Claude Project Chat may:

- inspect repository/public evidence that is directly readable;
- receive bounded exact-ref review packets prepared by Ryladmin or an owning lane;
- compare evidence, identify contradictions, falsify claims, surface uncertainty, and recommend changes;
- draft advisory prompts or review criteria when requested.

Claude Project Chat may not:

- commit, push, merge, create/mutate branches or tags, or mutate PRs/issues;
- modify a repository or registered worktree;
- write or reorganize the canonical Google Drive workspace;
- obtain or store a GitHub PAT, API key, password, provider credential, or other project secret;
- authorize provider traffic/spend, publication/deployment, Store submission, validation promotion, product/ODR decisions, Design taste, or phase transitions;
- dispatch Codex workers as an authority, select their runtime/model as an authority, or create a second backlog;
- convert its own conclusion directly into project law.

Technical access never widens this authorization.

## Private-repository packet fallback

If Claude Project Chat cannot directly read a required private repository, do not solve that by placing a repository credential in Chat.

Ryladmin may instead construct a bounded read-only packet from an already recovered authoritative repository state. A packet should identify, when applicable:

- source repository;
- exact commit/ref;
- included path list;
- exact Git blob identity and/or SHA-256 for included bytes;
- question/instruction hash;
- byte count and packet SHA-256;
- explicit omissions or unavailable surfaces.

Claude must treat such a packet as evidence only for its represented contents. Unrepresented current state remains unverified. The returned review is advisory evidence and must be reconciled by Ryladmin or the accountable owning lane before adoption.

This packet path is not C9A commissioning and does not itself authorize automated Claude dispatch.

## Claude Chat versus Claude Code

Claude Project Chat and Claude Code are separate capability surfaces.

This amendment admits the read-only **Chat** advisory lane only.

It does not commission Claude Code, change the preserved C9/C9A evidence, retry C9A R1/R2/R3, enable Claude subagents, enable mutation, or bypass any later MA-04 / Administrator admission requirement.

Any future Claude Code realization requires its own current authority, authentication/billing verification, tool/permission boundary, exact task packet, containment, evidence, and admission decision.

## Authentication and billing boundary

Claude Chat review must use the user's ordinary authenticated Claude subscription surface. This amendment does not authorize API-key/PAYG fallback, credential extraction, cloud-provider fallback, or automatic purchase of usage.

No claim is made here that Claude usage is free, unlimited, or measured as zero. Claude subscription usage and Codex account usage remain separate accounting questions.

## Quota interaction

Manual Director-initiated read-only Claude Chat review may be used while Codex is conserving allowance because it does not consume a Codex worktree/write lease.

This does **not** authorize Ryladmin to create new automatic Claude fan-out during LIGHT, CHECKPOINT_ONLY, WAITING_FOR_RESET, or USAGE_UNKNOWN. Existing Codex quota/write law continues to govern Administrator dispatch. Any future automated external-review policy requires measured support and its own admission.

## Review contract

A substantive Claude review should distinguish:

- **MEASURED** — directly supported by accessible current evidence;
- **INFERRED** — reasoned from evidence but not directly measured;
- **PROPOSED** — a recommendation rather than current authority.

Material findings should identify uncertainty and a falsifier where practical. Failed access is reported explicitly instead of filled from memory.

Claude may recommend that a problem deserves more or less reasoning, but actual executor/model/effort allocation remains governed by current Project/Ryladmin tooling policy and the accountable dispatcher.

## Integration and independence

Claude output is independent advisory evidence. It never self-promotes.

The owning Sol or Ryladmin must verify relevant facts against authoritative surfaces before adopting a recommendation. Protected Engineering authority changes still require accountable Engineering adoption. Design changes remain Design-owned. Shared Git/integration mechanics remain serialized.

The legacy Claude Project model that assigned Claude authority over Codex tasking, model/effort selection, or a four-agent governance hierarchy is historical and superseded for current operation.
