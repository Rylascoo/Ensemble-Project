# Project Parallel-Agent Operating Model — Director Amendment — 2026-09-13

Status: **DIRECTOR-APPROVED FOUNDATION; MULTI-AGENT RUNTIME ADMISSION STILL GATED**

## Purpose

This amendment expands pre-automation project throughput without creating additional project authorities, a second backlog, automatic chaining, or provider/validation authority.

The durable principle remains:

> **Parallelize mechanics and bounded reasoning; serialize authority and integration.**

This amendment does not alter the active E0 experiment method, current E0-C Director hold, scorer/mapping restrictions, provider authority, validation hierarchy, Design law, C10 falsification, or C11/Automation blocking.

## Accountable managers and delegated Relays

The project continues to have exactly one accountable Engineering manager and one accountable Design manager:

- **Engineering Sol** — accountable Engineering authority for `Rylascoo/Ensemble-Project`.
- **Design Sol** — accountable Design authority for `Rylascoo/Ensemble-Website` and its canonical visual-master workspace.

Two additional persistent ChatGPT manager contexts are admitted as delegated deputies:

- **Engineering Relay** — works only bounded Engineering leases delegated from current authority.
- **Design Relay** — works only bounded Design leases delegated from current authority.

A Relay is not a co-equal Sol, does not own `CURRENT_STATE.md`, does not independently transition the central queue, and cannot adopt its own work into lane authority. The accountable Sol reconciles Relay evidence before any authority-state change.
## Execution lease contract

Every Relay package must identify:

```text
LEASE ID:
ACCOUNTABLE SOL:
QUEUE ITEM:
REPOSITORY + EXACT REF:
ISOLATED WORKTREE / BRANCH:
OBJECTIVE:
ALLOWED SCOPE:
PROHIBITED AUTHORITY SURFACES:
REQUIRED VALIDATION / EVIDENCE:
PROGRESS TRANSPORT:
RETURN TARGET:
STOP CONDITIONS:
LEASE EXPIRY / COMPLETION CONDITION:
```

A lease grants work scope, not authority. One writer owns each leased worktree. Relays must stop and reconstruct when their material baseline moves or when the task becomes cross-lane, provider-bound, validation-promoting, ODR-bearing, or otherwise outside the lease.

GitHub Issues may carry lease dispatch, checkpoints, and returned evidence under the already-commissioned C6 transport law. Issues remain ephemeral transport only. `docs/PROJECT_EXECUTION_QUEUE.md` remains the single cross-project backlog/sequencing register.

## Administrator monitoring

The Administrator monitors repository-visible evidence—exact refs, worktrees, branches, PRs, CI, dispatch Issues, and sealed result artifacts—not hidden live chat state. Absence of a chat-inspection capability must never be replaced by inferred progress.

The Administrator may identify independent unblocked packages and propose/construct leases, but cannot make Engineering Relay or Design Relay into independent backlog owners or authorize work that the owning lane has not already earned.
## Administrator repository ownership split

`Rylascoo/Ensemble-Project` remains canonical for Administrator policy, security/authority boundaries, cross-project orchestration law, the C0-C13 gate contract, and the single project execution queue.

`Rylascoo/Ryladmin` is promoted from continuity-only storage to **Administrator Runtime + Continuity Authority**. It may canonically version the executable realization of already-approved Administrator law: launchers, role profiles, process supervision, shared-Git locking, runtime schemas/manifests, deterministic runtime tests, install/recovery/rollback tooling, and Administrator continuity records.

Ryladmin never becomes product, Engineering, Design, provider, validation, experiment, ODR, or project-backlog authority. If Ryladmin implementation conflicts with Project policy/specification, Project wins and the runtime must fail closed until reconciled.

Machine-local `C:\Users\Wiryl\.codex-ensemble` becomes a generated installation from one exact admitted Ryladmin commit plus local non-secret provenance. Runtime mutation must use an A/B boundary: the currently commissioned runtime judges a candidate isolated Ryladmin worktree; candidate code cannot overwrite the active runtime before merge, installation, and successor revalidation.

## Multi-agent admission sequence

Native subagents remain disabled in the commissioned runtime until separately proven:

1. **MA-01 — read-only Scout cell:** admit at most two read-only subagents under a read-only root; prove sandbox inheritance, process-tree containment, deterministic evidence, concurrency accounting, and no Git/provider/authority mutation.
2. **MA-02 — read-only Reviewer cell:** admit at most two read-only review subagents under the hardened Reviewer supervisor; root Reviewer alone emits the structured review contract.
3. **MA-03 — Worker child-inheritance test:** separately test whether a workspace-write Worker can spawn reliably enforced read-only children. If not proven, Worker remains the sole writer and consumes sealed Scout findings instead.
4. **MA-04 — Claude multi-agent review:** separately gate Claude Code subagents for selective R2/R3 advisory review only; current C9/C9A restrictions are not reinterpreted as permission.
5. **MA-05 — production economics:** run one real bounded package and measure wall-clock time, usage, coordination overhead, defects caught, and containment before raising concurrency.

Initial ceilings after admission: two top-level Codex jobs only when independent; at most two native subagents per root; one Claude review at a time. Shared Git, authority integration, provider authorization, validation promotion, and final merge remain serialized.

## Stop rule

No part of this amendment authorizes autonomous next-task pickup, automatic retry, automatic merge, Hooks, Automations, background polling, or recursive self-dispatch. Every production cycle returns to an accountable Sol/Administrator reconciliation boundary before another lease or dispatch can begin.
