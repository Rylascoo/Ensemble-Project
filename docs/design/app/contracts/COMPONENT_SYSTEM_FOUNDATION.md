## 1. Purpose

Define the Product-independent everyday control grammar that sits above the frozen Kymaean application architecture and static visual system.

This foundation exists because the accepted workspace families do not by themselves specify every object a creator touches repeatedly. It converts the selected visual mechanisms into reusable control behavior without inventing unresolved Product semantics.

Governing relationship:

`frozen architecture -> static visual system -> component foundation -> real workspace application -> later production/native handoff`

It is not:

`component reference -> shipping WinUI controls`.

## 3. Action hierarchy

Primary actions use monochrome hierarchy rather than accent color: Primary ink against Field, reversed as needed by theme. Teal is not the default action color.

Secondary actions use a functional boundary with transparent/field-relative interior. Quiet actions may remove persistent boundary chrome when their affordance remains clear. High-consequence actions use stronger structural separation and explicit language rather than depending on a warning hue.

Icon-only actions follow FICON F1: familiar Fluent/platform verbs remain visually quiet at rest, retain accessible names, and receive the same independent focus treatment as labeled actions. The deterministic reference uses at least a 32px icon carrier; this is design evidence, not a universal native token.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L42-L49); section 4.

## 4. Text and data entry

Text, search and multiline fields may use bounded control geometry because editable affordance requires a local surface. Their boundaries are functional controls, not the MAT identity mechanism.

Read-only state must be explicit in language or nearby task structure and may use a dashed boundary witness. Invalid state must provide corrective text and a stronger structural witness; color may reinforce later if authorized but cannot carry the state alone.

Placeholder text is support, not a substitute for a durable label when the field meaning would otherwise disappear after entry.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L50-L57); section 5.

## 5. Choice controls

Checkbox, radio and switch-style choices remain conventional controls rather than bespoke Kymaean symbols.

Accent may reinforce an already-established selected/on state because selection is a legitimate UI distinction. The state must remain understandable from control structure, check/position and associated text when hue is unavailable.

A switch is not a health/status indicator merely because it is on. Product meaning comes from its label and surrounding task.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L58-L65); section 6.

## 6. Collection rows

Lists and collections default to quiet rows and separators rather than repeated cards. A row may become locally bounded when interaction geometry requires it, but the collection should still read as one information structure.

Selection uses the STA F2 structural edge witness and may receive accent reinforcement. Keyboard focus is a separate outer ring and may occur on a different row. Selection never implies Director attention, Character agency, relationship strength, truth or effectiveness.

Secondary row actions remain subordinate to identity/content. Narrow layouts may move them below the primary row content without changing their semantic origin.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L66-L73); section 7.

## 7. Disclosure and transient surfaces

Progressive disclosure is preferred over permanently exposing secondary detail. Expanded content remains tied to its triggering context and does not become a new top-level mode by expansion alone.

Menus, flyouts and dialogs may use bounded surfaces and restrained elevation because temporary separation is functional. That elevation does not replace MAT F1 as the application identity mechanism and must not proliferate into ordinary content cards.

A consequential dialog must name the consequence and present an unambiguous safe alternative. Styling alone is not the warning.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L74-L81); section 8.

## 8. Semantic feedback

Pending, read-only, unavailable, invalid and related application states must be explicit in text and/or structure before hue.

The reference grammar may vary structural witnesses such as solid, dashed, dotted, double or stronger boundaries when they remain understandable in context. These witnesses are application UI state, not fictional Stage meaning.

Healthy persistence and ordinary success should remain quiet. Teal does not become a success, recovery, provider-health or validation color.

Source: [A:docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md](https://github.com/Rylascoo/Ensemble-Website/blob/33b8e13c4e71c8ceee1fdc3a646f291c9422a047/docs/KYMAEAN_APPUI_COMPONENT_SYSTEM_FOUNDATION_01.md#L82-L97); section 9.

## 9. Responsive and accessibility contract

The component foundation must survive the same semantic system across wide, medium and narrow layouts. Narrow layouts may stack actions, move subordinate row actions, sequence transient/detail surfaces and increase vertical depth; they may not require horizontal escape to preserve meaning.

Required design behavior:

- visible keyboard focus remains a solid outer ring independent from selection;
- icon-only controls retain accessible names;
- conventional icon carriers remain at least 32px in the deterministic reference;
- editable text controls retain usable control height while text may scroll internally when its value exceeds the field;
- forced colors remain comprehensible without authored hue;
- 200% text and text-spacing stress may increase vertical geometry but must not create page-level horizontal overflow;
- control meaning must not depend on hover, portrait recognition, motion, glow or theme.

The frozen APPUI-COMP-01 carrier passes 1600, 1024, 390 and 320 widths plus forced-colors 320, 200% text 320 and text-spacing stress 320 with zero layout overflow.

## 11. Change law

A later component may adapt literal dimensions to real task geometry while preserving this grammar. Changing primary-versus-accent action logic, focus/selection separation, card/tile restraint, hue-independent feedback or transient-surface role requires an explicit named successor with evidence.
